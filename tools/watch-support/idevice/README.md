# Non-destructive Watch connection probe

`WatchConnectionProbe.rs` is an overlay for the pinned idevice `3e55c84` FFI crate. Copy it to `ffi/src/watch_connection_probe.rs` and declare that module only when `companion_proxy`, `core_device_proxy`, and `rsd` features are available. The parent build integration owns the module declaration and feature selection. The probe does not require the `pair` feature.

`fairway_watch_connection_probe(adapter, handshake, expected_udid, report)` borrows an existing adapter and RSD handshake. Invoke it synchronously on their owning thread with exclusive access; keep both handles alive until it returns. Never dispatch these handles to another thread or use them concurrently. The C string and output pointer must be valid. A non-null `report` receives a string on both success and failure; free it with `idevice_string_free`. Free a returned FFI error with the normal idevice error-free API.

The probe checks the companion RSD service, requires exactly one registered Watch matching the expected normalized UDID, opens a fresh companion connection, and forwards Watch lockdown port 62078 using service name `com.apple.mobile.lockdownd`. It connects through the adapter and verifies lockdown `UniqueDeviceID` against the expected Watch. It performs neither an RSD check-in on Watch lockdown nor pairing/session/installation/transfer/deletion operations. The companion shim's own `connect_rsd` performs its required RSD check-in internally.

The main probe has a 50-second deadline, with three connection attempts capped at five seconds each. Once forwarding has been attempted, including an ambiguous timeout while its request is in flight, cleanup always runs outside the cancelled probe future. Cleanup makes up to two fresh companion connections, each with a five-second deadline, and stops forwarding **remote Watch port 62078**, not the returned local port. Cleanup failure prevents success. Maximum normal async wait budget is 60 seconds; runtime scheduling may add a small overhead. Success means only that the native Watch lockdown endpoint answered its identity request and forwarding cleanup succeeded. It does not demonstrate pairing, install support, or refresh success.

The report contains only the closed stage names, booleans, and closed outcome codes. Upstream error messages, registry contents, UDIDs, pairing identifiers/keys, and plists are never inserted into it or the returned FFI error. Optional product/version queries are intentionally omitted. Existing idevice internal logging is outside this report contract; integration must keep verbose/protocol logging disabled when collecting a shareable report.

Unit tests cover UDID format boundaries, exact single-Watch registry matching, cleanup overriding an otherwise successful probe, failure-stage preservation, and the report's closed schema. The parent CI compiles this overlay against the pinned source and runs these tests; no physical device test is implied.
