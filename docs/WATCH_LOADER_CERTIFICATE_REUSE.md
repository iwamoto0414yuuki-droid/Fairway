# Watch Loader：証明書上限7460への対応

2026-10-25。対象版：2.3.1-auth.20261025.2。

利用者の前版でのエラーは `Failed to retrieve certificate identity / Developer error 7460`。
認証後の証明書取得まで進んだことを示す。既存証明書の上限で停止しており、Watch導入の失敗を証明するログではない。
利用者は、このWindows PCの通常版iloaderでSideStoreを導入したと回答している。

## 方針

通常版iloaderに元の秘密鍵が残っていれば、その鍵とAppleの現在のチームにある証明書を照合して再利用する。
試験版は通常版と異なる保管領域を使っていたため、そのままでは元の鍵を利用できなかった。
さらに元コードは証明書のmachine_nameの一致を要求していた。公開鍵が一致しても、アプリ名が違えば再利用されない。
今回、照合を実際の公開鍵と証明書の有効期間に基づく処理へ変更した。

認証やWatch導入の汎用的な成功保証ではない。元の鍵が失われた場合、別PCで作った場合、証明書が失効・期限切れの場合は再利用できない。

## 利用者の操作

1. 前の試験版と通常版iloaderを閉じ、新版ZIPをすべて展開する。
2. Fairway-Watch-Loader.exeを起動し、版番号の末尾が`.2`であることを確認する。
3. SideStore導入時と同じApple Accountで「認証を確認（Login）」を押す。
4. 「通常版iloaderの署名鍵を再利用」を押し、成功の表示を確認する。
5. iPhoneをUSB接続・選択し、Import IPAから同梱のFairway-0.3.0-unsigned.ipaを選ぶ。
6. iPhoneとWatchで起動し、スコア保存・同期を確認する。次回の期限更新も別途実機確認する。

「Don't use keyring」はオフ。鍵を見つけられない・照合できない場合は停止し、その表示を確認する。
Revoke、証明書削除、SideStoreの削除・ログアウトは行わない。

## 読み書きの範囲

明示操作時だけ、同じメールアドレスのSHA256/keyを通常版の`iloader`資格情報ストアから読む。
Appleの現在のチームの証明書一覧を取得し、実際の公開鍵・有効期間・machine_idを確認する。
一致した場合だけ、試験版の資格情報ストアへその鍵を保存する。元の保存領域は変更しない。
パスワード、認証コード、Anisette状態、ペアリング情報はこの処理ではコピーしない。
鍵は画面やログへ返さず、鍵ファイルを書き出さず、CIにも渡さない。
資格情報ストアが無効な場合はファイル保存へ切り替えず停止する。

鍵再利用ボタン自体には証明書の作成・取消を行う呼出しがない。
Import IPAには通常の署名・登録・プロファイル取得が必要で、証明書が使えない場合は引き続き上限エラーで停止する。

## 検証

合成したRSA鍵と証明書で、異なるmachine_nameでも一致を認めること、異なる鍵・不正な鍵・証明書なしでは保存しないこと、照合成功時の保存を検査する。
元からある認証21件とWatch関連3件も継続する。実行結果とビルドの記録は同梱verification.jsonとoffline-tests.logで確認する。
Watchの登録・親子ID・プロファイル・転送の元コードは変更しない。証明書識別を扱うcert_identity.rsは今回の変更対象であり、未変更ファイル一覧からは明示的に除外する。

この再利用処理およびWatchでの起動・期限更新は、受け取り側での実機確認が必要。
